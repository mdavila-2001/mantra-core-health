# H2.S3 — Diagramas Mermaid y construcción de la documentación

Fecha: 2026-10-21

## 1. Todos los diagramas parsean (mermaid 11.4.1 en Chromium)

Se extrajeron los bloques ```mermaid de docs/inventario/flujos/*.md y se pasó cada uno por mermaid.parse en un navegador real.

```text
$ node validar.mjs docs/inventario/flujos
{"diagramas":1205,"invalidos":0,"maxLen":8393}
[]
```

Control negativo: el mismo validador sobre un diagrama roto a propósito.

```text
{"diagramas":1,"invalidos":1,"maxLen":25}
```

Tamaño del mayor diagrama: 8 393 caracteres (límite por defecto de mermaid: 50 000).

## 2. mkdocs build --strict

```text
$ python3 -m mkdocs build --strict            # configuración del repositorio
WARNING -  MERMAID2  - Cannot check URL, no Internet access? (https://unpkg.com/mermaid@10.4.0/dist/mermaid.esm.min.mjs)
Aborted with 1 warnings in strict mode!
$ curl -sS -o /dev/null -w "%{http_code}" https://unpkg.com/mermaid@10.4.0/dist/mermaid.esm.min.mjs
curl: (56) CONNECT tunnel failed, response 403
```

Clasificación (regla 80.4): ENVIRONMENT. El plugin mermaid2 comprueba la URL de unpkg y la política de red del entorno la bloquea. El mismo aviso aparece **excluyendo** docs/inventario/flujos (hay diagramas Mermaid en docs/observability desde antes), así que no lo causan las páginas nuevas.

Para verificar igualmente el contenido, se construyó con una configuración temporal (fuera del repositorio) que sirve mermaid desde un archivo local:

```text
$ python3 -m mkdocs build --strict -f <temporal>/mkdocs-local.yml
INFO    -  Documentation built in 52.32 seconds
exit=0
```

**No cubierto:** la construcción con la configuración real del repositorio queda BLOQUEADA en este entorno por la red; en uno con acceso a unpkg el aviso no debería aparecer. mermaid.parse valida la sintaxis, no que el diseño de cada diagrama sea legible: se miró a ojo uno (holds).
