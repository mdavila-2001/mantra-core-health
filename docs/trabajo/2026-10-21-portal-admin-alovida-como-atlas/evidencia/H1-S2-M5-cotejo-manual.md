## Defectos encontrados en mi análisis por este cotejo (todos corregidos y con prueba)

1. **Falso positivo de actualización** (#5): variables con tipo envoltorio contaban como instancias. Antes 715 pares tabla-operación `POR_TIPO`, después 712. Prueba: `datos.test.mjs` «una variable FilterQuery<E> o Partial<E> no es una instancia…»; se comprobó que **falla sin el arreglo y pasa con él**, y además que `GET /scheduling/slots` quedó sólo en LEE.
2. **Falso negativo por despacho dinámico** (#4): el historial se escribe en una tabla elegida por un argumento. Se resuelve cuando el llamador pasa un literal o una constante (56 efectos `POR_REGISTRO`); cuando el argumento viene del cliente (#7), se informa. Pruebas: «despacho por registro» ×2 en `datos.test.mjs`.
3. Hallados antes de esta tabla y por el mismo método (leer el código ante un resultado raro): puertos con una o varias implementaciones que se ignoraban (+ `POST /scheduling/waitlist` y otras), alias de importación (`import { X as Y }`), nombres de clase repetidos entre módulos, vistas SQL con nombre armado desde constantes, y un error mío de edición que cortaba la cadena de llamadas (lo detectaron las pruebas: 6 fallos, corregido).
