# Construir un sistema visual coherente

Traducir la dirección estética en reglas que funcionen con datos y estados reales. Consultar [criterios de decisión](references/decisiones.md) al fijar tokens y materiales.

## Procedimiento

1. Identificar tareas, densidad, identidad existente y restricciones de plataforma.
2. Definir jerarquía, tipografía, ritmo espacial, superficies y uso del acento. Describir decisiones concretas, no solo adjetivos.
3. Crear valores base y roles semánticos. Mantener excepciones de componente solo cuando tengan razón funcional.
4. Aplicar la dirección en una pantalla patrón con contenido realista, móvil y estados vacío/error/ocupado.
5. Medir contraste y revisar texto largo, zoom, foco y fallback de efectos. Adaptar tema oscuro solo si está en alcance.
6. Propagar decisiones que sobrevivan al piloto y retirar duplicados gradualmente.

## Salida

Entregar dirección visual, catálogo de roles, reglas de composición, pantalla patrón y evidencia de revisión. Identificar valores propuestos frente a requisitos normativos.

## Límites

Inspiración Apple significa cuidado de jerarquía y respuesta; no autoriza copiar activos ni obliga a usar cristal. Evitar cambios de stack por estética. Conservar identidad y funcionalidad. No certificar contraste de superficies dinámicas midiendo solo un fondo favorable.
