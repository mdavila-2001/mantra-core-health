# Smoke H1: alta médica navegador → API → PostgreSQL

Fecha: 2026-09-24. Fuente funcional: `02_METAPROMPT_MEDICO.md`, SHA-256 `b57dfd316c4d642eb5e1db49257397b8fd2864b511317282ae4b70ff1262a656`.

El smoke corrió en Chromium con frontend `justin/medical-module-execution-20260924` (`df611861`) y API de la misma rama (`783d2697`). Angular usó configuración `real-api` (`mockBackend=false`) y proxy de mismo origen a `localhost:3000`. La API usó PostgreSQL 18 desechable (`mch_medical_test`), `ORM_SCHEMA_SYNC=off` y almacenamiento local en `/tmp`. No se cargó `.env`, no se cambió `proxy.conf.json` ni se alteró CORS.

El archivo Playwright temporal terminó con **4/4 pruebas aprobadas**. Para el mismo actor, el recorrido creó dos filas universitarias con nombre, número, institución y PDFs distintos. Las dos llamadas a `POST /iam/auth/upload-registration-document` devolvieron 201; `POST /iam/auth/register-practitioner`, 201. Después, el test inició sesión por `/iam/auth/login` (200), leyó `/profiles/practitioners/me/summary` (200) y obtuvo ambas credenciales con sus instituciones y archivos. Descargó los dos PDFs mediante `/common/files/:id/content` (200 en ambos; tipo PDF y firma `%PDF-1.4`), actualizó una credencial mediante PATCH (204), recargó la página y volvió a leer el cambio desde el resumen (200). Una consulta de verificación en PostgreSQL encontró dos credenciales y dos `fileId` distintos para cada uno de los tres perfiles sintéticos de las corridas.

Las otras tres pruebas comprobaron la opcionalidad del lugar de estudio, persistencia visual al avanzar/volver y geometría móvil. La captura móvil fue inspeccionada y está en [registro-medico-mobile.png](registro-medico-mobile.png).

El primer intento de la prueba ampliada terminó antes de abrir el formulario porque el frontend no estaba levantado (`ERR_CONNECTION_REFUSED` en el puerto 4390). Tras iniciar `ng serve --configuration real-api`, la corrida completa pasó 4/4. El comando final fue `E2E_BASE_URL=http://127.0.0.1:4390 corepack yarn pw playwright/medical-real-api.temp.spec.ts --workers=1`. La especificación temporal se retiró después; no queda como test permanente ni cuenta como parte de la suite estable.

La integración API separada `practitioner-credential-registration-files.int-spec.ts` pasó 1/1 y verificó diez credenciales (dos títulos y dos de cada tipo de posgrado), lectura privada, ocultamiento público, descarga del dueño y rechazo de reutilización. Esos diez registros pertenecen a otro actor. Después de ambas pruebas, un test temporal de limpieza pasó 1/1, retiró los tres perfiles y seis credenciales sintéticas del PostgreSQL desechable; la consulta de control devolvió cero filas `MED-REAL`. También se retiraron los bytes almacenados bajo `/tmp`, los archivos temporales y los dos servidores locales. MED-E01 permanece A MEDIAS; el plan sigue en 0/98 criterios con DoD completo.
