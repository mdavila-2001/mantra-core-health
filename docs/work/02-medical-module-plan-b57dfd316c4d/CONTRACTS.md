# Contratos y dependencias — observados con alcance limitado

Este inventario combina lectura de contratos con una ampliación de ejecución autorizada por el propietario el 2026-09-24. La rama aislada `justin/medical-module-execution-20260924` añade PATCH de credenciales propias, adjuntos por fila, serialización concurrente de citas por profesional y lectura/edición de dirección/GPS laborales (`ADDR_USE_WORK`) con soporte para varias sedes propias. La continuación H1 también captura y persiste dirección/GPS laborales durante el alta profesional, separadas de HOME. La última continuación hace obligatorios en el DTO el CI y su departamento emisor, valida el catálogo antes de escribir y añade identidades sintéticas a los fixtures de integración; sus pruebas son unitarias y no se ejecutaron contra PostgreSQL. No se editó el modelo. La API se probó con diez documentos sintéticos y FX-2/FX-9 en PostgreSQL 18 efímero; un smoke Chromium→API→PostgreSQL adicional probó ocho credenciales de los cuatro tipos visibles, tres especialidades y ocho PDFs para un mismo actor. Las nuevas pruebas del alta laboral/CI son unitarias, no contra PostgreSQL. Estos resultados parciales no equivalen a init DDL canónica ni al journey integral de los 17 escenarios Médico.

## Alta propia — correos personal/de acceso y laboral (L0179, L0186)

En el DTO de alta, `email` sigue siendo el identificador de acceso. Cuando el cliente también envía `workEmail`, `email` se declara como contacto personal (`CONTACT_USE_HOME`) y `workEmail` como laboral (`CONTACT_USE_WORK`). El campo laboral es opcional para conservar clientes anteriores: sin `workEmail`, `email` se persiste como contacto WORK y el campo existente `personalEmail` continúa opcional. El contrato de lectura propia devuelve `workEmail` y `personalEmail` según su uso; el frontend prefiere esos campos explícitos y conserva `email` como alias compatible. Los tests unitarios verifican validación y selección de usos; el spec `profiles-practitioners.service.spec.ts` (138/138) verifica además que la lectura privada conserva correos HOME/WORK distintos. La persistencia real y lectura tras recarga no se ejecutaron en esta continuación, así que MED-E03 sigue `A MEDIAS`; no se cambia modelo ni DDL.
